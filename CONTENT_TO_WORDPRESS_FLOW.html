Editorial publishing workflow

HTML/PDF content to WordPress

A human-reviewed prompt prepares document content, then post.http carries the approved data into the WordPress REST API.

1. Source

HTML or PDF

Original document, images, headings, links, and metadata.

2. Extract

Readable content

Convert the source into clean text, image files, and document context.

3. Prompt

Prepare content

Generate a title, WordPress-safe HTML, excerpt, category recommendation, and media selection.

4. API handoff

post.http

Map approved fields to authenticated REST API requests and create a draft.

5. CMS

WordPress

Review the stored draft, revise if needed, and publish when editorial approval is complete.

Prompt-to-payload touchpoints

1
Extract source materialPreserve the readable text, images, attribution, and source metadata.
2
Prepare and review prompt outputApprove the title, HTML body, excerpt, taxonomy recommendation, and media before it reaches the CMS.
3
Map values into the draft payloadUse the approved values as title, content, excerpt, categories, and featured_media.
4
Publish only after CMS reviewThe initial API request uses status: draft; publishing is a separate approved action.

post.http request sequence

GET /users/me?context=editVerify credentials and author permissions from the local .env file.
GET /categories?context=editFind the category ID, or POST /categories to create it.
POST /mediaUpload an optional image or source asset and retain the returned media ID.
POST /postsCreate the reviewed content as a WordPress draft.
POST /posts/{postId}Update editorial changes, then send status: publish when approved.
Key handoff: the approved prompt output becomes the JSON body in POST /posts. The WordPress API receives a draft first; CMS review controls publication.
